## D5 LLM 裁判的可靠性

**要点**：整个评测都靠 LLM 裁判打分。我们看到了几种已知的偏差，并在设计上加以控制；但分数仍应理解为"相对比较"，不能当作绝对质量。

| 现象 | 证据 | 出处 |
|---|---|---|
| 位置偏差 | 第 1 轮中，第一位裁判 21 次里有 17 次选了排在第二个的答案，而 C 只有 10 次排在第二 | `04-evaluation/02-dev-rounds/round-01/analysis-zh.md` 第 2 节 |
| 相对打分 | 完全相同的 7 份 A 答案（Opus），第 1 轮均分 7.73，第 2 轮 7.46。C 变强以后，A 的分数被压低了 | 第 1 轮和第 2 轮的 `results.md` |
| 裁判自己算错 | opus-U6-j2 把 C 写的"50 年超越概率 48%"判为错误，但 1 − 0.987⁵⁰ = 0.48，C 是对的 | `round-01/analysis-zh.md` |
| 裁判之间观点相反 | 第 1 轮 U5，两位 Opus 裁判对"下库该先放空还是先缓冲"给出相反的判断 | `03-skills/revisions/human-review-notes-zh.md` 例 1 |
| 长度效应 | 最终测试中 C 的答案比 A 长 32%（3,834 词对 2,911 词）；长度差与分差的相关系数，第 1 轮 r = 0.24（21 个点），第 2 轮 r = 0.79（7 个点） | `04-evaluation/03-final-test/results.md`；各轮的 `analysis-tables.md` |
| 同模型裁判 | 裁判和主要答题模型都是 Opus 5.5，可能偏好同一种写法 | — |

**我们的控制办法**：
- 盲评，答案文件名随机；
- 第二位裁判看到的答案顺序相反；
- 两位裁判一致才算胜；
- 裁判 prompt 写明不因长度给分；
- 关键结论由人复核，例如核对裁判的算术。

**可以怎么说**：更可靠的结论是胜负方向和"明显胜出"票数，平均分差会被放大。下一步可以加入人工专家评分，或换用不同家族的模型做裁判。

## D6 skill 自己会引入系统性错误

**要点**：skill 让答案更完整，但它写的公式和规则会被模型当成模板，用到不适用的场合。

- **J02 的公式被套错**：J02 给的是"等相关"误差之和的方差 nσ²(1+(n−1)ρ)。最终测试中，C 组把它用在了逐时自相关的误差上，夸大了累积误差，例如 V04-S 写出"24 h 误差是独立假设下的 4.4 倍"。裁判在 V03-D、V04-S、V04-D 三处指出这个问题，而 A 组没有出现。出处：`04-evaluation/03-final-test/rc-analysis-zh.md` 第 4 节、`judgments/V04-S-j2.md`。
- **把 skill 当成文献引用**：第 1 轮中，Haiku 有 5 道题、Sonnet 有 3 道题写了"papers show…"一类的话，A 组一次也没有。v2 加了禁止规则之后，Opus 的答案里再没有出现。出处：`round-01/analysis-zh.md` 第 4 节。
- **通用内容挤占方法设计**：在最终测试中 C 的 RC 低于 A 的几份判定里，扣分都集中在"优化、多情景聚合、目标形式化写得更空"。出处：`rc-analysis-zh.md` 第 3 节。

**启示**：skill 里的公式和规则必须写明适用条件（例如"按误差的实际自相关结构计算"）。也就是说，skill 要教的是"该问什么"，而不是"套什么"。按测试方案，最终测试后不再修改 skill，这一点留作下一版的改进。

## D7 人在回路中的作用

**要点**：裁判意见能发现问题，但不能决定怎么改。几个关键转折都来自人的判断。

| 人的决定 | 作用 | 出处 |
|---|---|---|
| skill 只写 pattern 推导出来的内容，其他内容要等裁判提出意见后才加入 | 保证 skill 的每一条都可以追溯来源 | `03-skills/README.md` |
| 防洪区要尽快排空，洪水期间除外（J13） | 在两位裁判意见相反时，给出"规则加例外" | `human-review-notes-zh.md` 例 1 |
| "Optional" 的意思是"涉及就要考虑"，不是"可以不考虑" | 修正了 AI 把"证据少"写成"可以跳过"的问题；U5 因此从意见不一变成 3/3 胜出 | 同上，例 2；`round-03-report-zh.md` |
| 不采用 Haiku 的结果，以 Opus 为准 | 确定修改依据和测试范围 | `03-skills/revisions/changes-v1-to-v2-zh.md` |
| 简单版和详细版两种 brief、固定格式 | 让最终测试能区分"题目详细程度"和"skill"各自的影响 | `04-evaluation/03-final-test/protocol.md` |

**可以怎么说**：AI 负责找分歧、列证据、执行修改；人负责给出领域规则和适用边界。这种分工比"裁判说什么就改什么"更可靠。

## D8 题目怎么问，可能比 skill 更重要

**要点**：在最终测试里，brief 写得详细，比加 skill 更能让答案覆盖论文自己的研究路线。

- RC（论文路线覆盖）：
  - A 组：简单版 6.6 → 详细版 6.8（+0.2）
  - C 组：简单版 6.2 → 详细版 7.0（+0.8）
- 不少论文要点只有在详细版里才有人覆盖，A、C 两组都是如此。例如 V01 的逐日选择预见期、V04 的一组由简到繁的误差假设、V05 的分频率规则集。
- 胜负上，两种 brief 一样，都是 C 4 胜 0 负 1 意见不一，所以 skill 的优势并不依赖题目的详细程度。

出处：`04-evaluation/03-final-test/results.md`、`rc-analysis-zh.md` 第 2 和第 4 节；图见 `06-discussion/d2-reference-coverage/figures/fig6-reference-coverage-matrix`。

**可以怎么说**：skill 教的是专家的"流程和把关"；方法层面的切入点，很大程度上来自问题本身是怎么提的。这提示：把问题界定清楚，本身就是专家能力的一部分。可以作为下一版 skill 的方向，比如在"界定问题"这一段加入方法层面的提问。

## D9 泛化性和外部效度

- **留出论文少、主题单一**：只有 5 篇，都属于"洪水风险下的水库调度"。结论只能推到同一主题。
- **跨版本重复出现**：旧版最终测试（2026-10-09，旧 skill，700 字四节格式）的结果是 C 5 胜 0 负，RC 6.3 对 6.3。这一版是 C 8 胜 0 负 2 意见不一，RC 6.7 对 6.6。"skill 胜出、但 RC 不变"在两次格式不同的测试里都出现了。出处：`04-evaluation/03-final-test/final-report-zh.md` 第 4 节。
- **reference 由 AI 撰写**：最终测试的 reference 是子代理读论文写的，裁判没有读原文；我们只核对了 reference 和 brief 的研究问题一致，V01 对照过原文。
- **只测了一次**：除第 3 轮外，每个版本每道题只作答一次，没有重复。
- **只测了 Opus**：最终测试只用了 Opus 5.5；其他模型的情况见 D3。
