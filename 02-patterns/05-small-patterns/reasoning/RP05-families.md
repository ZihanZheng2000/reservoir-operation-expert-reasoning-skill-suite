# RP05 小 pattern：判断物理与运行上的可行性

日期：2026-10-01 | 状态：已定稿 | 编码者：Claude Code | 方法同 [`RP01-families.md`](RP01-families.md)

**大 pattern 问题：** 提议的预泄、目标水位或放水调整，在时间、空间、设施和制度上能不能真正做到？

**证据：** RP05 的全部匹配：40 步，25 篇论文（primary 19，secondary 21）。逐条分配见 [`RP05-assignment.csv`](RP05-assignment.csv)。分组依据是"哪一类条件限制了调整"。

|---|---|---:|---:|---|

| **RP05-B** 时间上来不来得及 | 预见期内能否腾空或完成预泄；预见期越长，可调的上限越高 | 8 | 7 | 成熟 |

## 2. 小 pattern 定义

### RP05-A 设施与运行的硬约束
- **触发条件：** 候选方案可能突破水位、库容、泄流能力、出库变幅或爬坡速率的限制。
- **识别后要做的事：** 把这些限制写成硬约束，排除违反的方案；区分硬约束和软目标。例如期末水位通常是软约束（E02）。
- **预期产出：** 约束清单及硬 / 软属性。
- **代表证据：** E22-R4（变幅限制用来防止下游河道冲刷）；E37-R8（一次性大幅改变泄量本身不安全）；E48-R3（防洪库容小的水库只能按泄流能力运行）。

### RP05-B 时间上来不来得及
- **触发条件：** 预泄或腾库需要时间，而洪水到来之前的预见期有限。
- **识别后要做的事：** 比较"按最大安全泄量腾空所需的时间"和"有效预见期"，由此限定可以抬高的水位；考虑预报失败、下一场洪水立即到来的最坏情况。
- **预期产出：** 时间可行的上限水位或预泄方案。
- **代表证据：** E01-R3、E19-R6（48 小时内能完成预泄的上限 66 m）；E09-R4（最坏情况下来不及泄掉的水量要扣除）。
- **与 RP03-B 的边界：** RP03-B 判断"预报能提供多长的预见期"；RP05-B 判断"在这段时间内，水库能否完成动作"。

### RP05-C 库容空间够不够
- **触发条件：** 调整需要占用或腾出库容，需要判断剩余空间能否承接洪水，以及放掉的水能否回蓄。
- **包含：** 剩余过流能力在蓄水与安全裕度之间分配（E05）；可多蓄的水量（E09）；预报时段内的设计洪量（E11）；无洪水时能否回蓄到汛限水位（E12、E16）；超出库容时截断分配（E24）；不同量级的洪水能否被对冲改变（E25）。
- **识别后要做的事：** 列出可用空间与需要承接、回蓄的水量，确定可行区间。
- **预期产出：** 可行的库容 / 水位区间。

### RP05-D 下游与系统条件限制本地动作（待定）
- **触发条件：** 水库本身能放，但汇流时间、河道槽蓄、未控区间来水或其他水库的状态会限制效果。
- **代表证据：** E43（预见期要覆盖最远水库的汇流时间；区间来水造成残余超标）；E44（河道槽蓄、聚合后的降泄顺序）。只有 2 篇论文，因此标为待定。

### RP05-E 模型上可行不等于实际能实施
- **触发条件：** 方案要用于实际调度，或者要推广到其他水库。
- **包含：** 必须符合法规规定的调度线做法和指定工具（E18）；需要管理部门协作和实时能力（E20）；需要多部门授权（E21）；计算耗时和数据缺口（E22）；机构的保守倾向（E25）；效果取决于各地的工程设施条件（E17）。
- **识别后要做的事：** 列出实施的前提条件，判断哪些已经具备、哪些缺失。
- **预期产出：** 实施前提清单及缺口。
- **与 EP11 的边界：** RP05-E 只判断条件是否具备；真正去协商、试点、修订规程属于 EP11。
