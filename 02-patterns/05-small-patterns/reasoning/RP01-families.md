# RP01 小 pattern：诊断现有调度规则的局限

日期：2026-10-01 | 状态：已定稿 | 编码者：Claude Code

**大 pattern 问题：** 现有的水库调度规则在什么条件下无法兼顾防洪风险与其他目标？哪些局限说明它需要调整？

**证据来源：** `../03-step-coding/step-pattern-matches.csv`，RP01 的全部匹配：19 步，18 篇论文。其中 RP01 为主角的 16 步，为配角的 3 步。逐条分配见 [`RP01-assignment.csv`](RP01-assignment.csv)。

**方法：**
1. 逐条读取完整抽取内容，写出"情境码"。
2. 用持续比较法分组。分组的判断标准是"局限的来源"：规则的哪一部分出了问题，以及识别之后要做的事是否不同。
3. 写出定义。

## 1. 总览

| 小 pattern | 一句话 | 步骤 | 论文 | 证据强度 |
|---|---|---:|---:|---|
| **RP01-A** 固定的防洪库容分配造成安全–效益失衡 | 规则用固定的汛限水位、调度线或防洪库容，导致小洪水时浪费水量，或大洪水时保护不足 | 10 | 10 | 成熟 |
| **RP01-B** 规则用不上已有的预报信息或其不确定性 | 预报已经存在，但规则只看当前状态、只用确定性预报，或预见期太短 | 4 | 4 | 成熟 |
| **RP01-C** 规则的决策边界漏掉了系统对象 | 规则只管本库，忽略了梯级耦合或下游控制点 | 2 | 2 | 待定 |
| **RP01-D** 规则的制定依据已经过时或过窄 | 规则依据的规程年代、平稳性假设或率定事件已经不再成立，或者本来就太少 | 3 | 3 | 成熟（刚达到门槛） |

另有 6 步以 RP01-B 为副小 pattern，2 步以 RP01-D 为副小 pattern（见分配表），不计入上表的步骤数。

## 2. 小 pattern 定义

### RP01-A 固定的防洪库容分配造成安全–效益失衡

- **触发条件：** 规则在整个汛期或某个季节段，使用固定的汛限水位、调度线或防洪库容；而洪水的发生时间、量级在不同年份差别很大。
- **包含：** 小洪水年份白白腾空库容、弃水、汛后蓄不满、供水或发电损失；大洪水时同一个固定值又可能不够。
- **不包含：** 规则的问题在于"没用上预报"（归 RP01-B）；在于"依据过时"（归 RP01-D）；只是一般性的目标冲突、并没有指出现有规则的缺陷（归 RP06）。
- **识别后要做的事：** 说清楚固定值在哪种情况下失衡、失衡的方向（过保守还是保护不足），以及它原本要保证的安全目的；然后提出"在保证安全的前提下允许动态调整"的方向。
- **预期产出：** 一句有边界的诊断，例如"固定 145 m 汛限水位在中小洪水年份造成弃水，需在不增加防洪风险的前提下设定动态上限"。
- **代表证据：**
  - E03-R1：静态汛限水位按设计洪水确定，忽略年内来水变化，导致弃水、汛后缺水，汛期推迟时还可能暴露风险。
  - E05-R1：固定防洪库容在无大洪水时闲置，在大洪水时又不足。
  - E07-R1：调度线按气候平均设定，2012–2013 年在干旱前仍按名义防洪库容放水。
  - 其他：E01、E19、E29、E34、E41、E44、E50。

### RP01-B 规则用不上已有的预报信息或其不确定性

- **触发条件：** 已经有可用的预报，但现有规则只根据当前状态决策；或者虽然用了预报，却只当作确定值、没考虑误差；或者所用预报的预见期太短，来不及提前准备。
- **包含：** 常规规则不使用预报（E15、E23）；基于库容约束的预泄规则没有考虑预报误差风险（E26）；现有预报驱动方案的信息来得太晚（E19-R2）。
- **不包含：** 预报本身是否可靠、能支持哪些动作（归 RP03）；识别有哪些不确定性来源（归 RP02）。RP01-B 只判断"规则有没有把这些信息用进去"。
- **识别后要做的事：** 指出规则缺了哪一类信息（预报值、预报不确定性，还是更早的前兆信息），以及缺了它会在什么情况下导致错误决策。然后把"预报和不确定性如何进入规则"交给 RP02、RP03 去判断。
- **预期产出：** "规则需要引入某类信息"的诊断，并注明这类信息目前的可用性。
- **代表证据：**
  - E15-R1：常规规则只看当前状态，不用未来预报和预报不确定性。
  - E23-R1：离线规则不用预报；确定性预报驱动的预泄在洪水未到时很脆弱。
  - E26-R1（配角）：基于库容约束的预泄规则没有考虑预报误差。

### RP01-C 规则的决策边界漏掉了系统对象（待定）

- **触发条件：** 规则只针对单座水库或本地目标，但实际洪水风险取决于其他水库、支流汇流或下游控制点。
- **包含：** 各库独立按规则运行，忽略干支流洪峰遭遇（E21）；本地运行只看库水位和发电，不考虑下游城市的洪水风险（E43）。
- **不包含：** 只是多个目标之间的权衡，并没有遗漏系统对象（归 RP06）。
- **识别后要做的事：** 说明遗漏了哪个对象、它通过什么途径影响风险（汇流时间、洪峰遭遇、下游河道能力），再把决策边界扩大到需要协调的范围。
- **预期产出：** "需要从单库规则扩展为系统协调"的诊断，并列出需要纳入的对象。
- **证据强度：** 只有 2 篇论文，标为待定。

### RP01-D 规则的制定依据已经过时或过窄

- **触发条件：** 规则当初依据的条件已经变化，或者依据本身就太窄。例如：规程制定于几十年前，流域已经改变、预报技术已经进步；规则假设洪水频率平稳，但实际上不平稳；规则参数只用少数几场洪水或凭用户经验率定。
- **包含：** E18（规程年代久远）；E45（洪水概率非平稳）；E20-R2（少数事件率定或人工调参）。
- **不包含：** 规则本身的结构就是固定值（归 RP01-A）；对研究证据本身的检验，例如回报期数据不足、对比是否公平（归 RP09）。
- **识别后要做的事：** 指出是哪个依据失效（时间、平稳性还是率定样本），检查它是否仍然成立；然后提出重新率定或重新推导规则的需求。
- **预期产出：** "规则依据需要更新"的诊断，并注明需要什么新的证据，例如更长的序列、非平稳频率分析、更广的情景集合。
- **证据强度：** 3 篇论文，刚好达到"成熟"的门槛。

## 3. 区分规则（编码时用）

一步证据同时涉及多个小 pattern 时，按"论文认为问题的**根源**是什么"来判断主小 pattern：

| 如果根源是…… | 主小 pattern |
|---|---|
| 规则的数值是固定的，不随年份或季节变化 | A |
| 有信息可用，但规则没有用上，或用法忽略了不确定性 | B |
| 规则管的范围太小，漏掉了其他水库或下游对象 | C |
| 规则当初依据的条件或样本不再成立 | D |

难判断的例子：
- **E03-R1**：既说固定值不随季节变化（A），也说没用实时信息（B）。论文的论证重点是"静态值导致弃水、缺水"，因此主小 pattern 为 A，副小 pattern 为 B。
- **E18-R1**：既说规程旧（D），也说没用现代预报（B）。论文的论证重点是规程年代久、流域条件已变，因此主小 pattern 为 D，副小 pattern 为 B。

## 4. 局限

- 分组和定义由同一编码者完成；第 3 节的区分规则只做了自测，尚未做独立编码检验。
- 证据都是论文的"研究动机"段落，反映的是作者如何论证规则需要调整，不等于现实中调度机构的诊断过程。
