# Round 03 结果报告（skill v3，只测 U5，Opus）

日期：2026-10-28

## 测试设置

- **答题**：C 组用 Opus 5.5 加 skill v3 回答 U5，独立回答 3 次（r1–r3）。skill v3 冻结在 `skill-tested/`。
- **对照**：每次都与第一轮 Opus 的 U5 A 答案配对。A 答案内容逐字节相同，每次配对都换一个新的随机文件名。
- **评判**：
  - 每次配对由 2 位 Opus 5.5 裁判盲评，两位看到的答案顺序相反。
  - 题目、答题 prompt 和裁判 prompt 都与前两轮相同。
- **判定标准**（事先约定）：3 次中至少赢 2 次，才算修好。
- **运行情况**：第一次启动时，3 个答题 agent 都因会话额度用完而失败，没有写出任何文件。额度重置后全部重跑。

## v3 改动起作用的地方（裁判意见）

- **J23（支流洪水到达时间的情景）**：三份答案都写到了支流洪水早到、同时到、晚到的情况，正好补上第二轮的缺口。
- **J24（联合库容与坝间协调）**：三份答案都写到了两座坝之间的协调。r3 还指出支流先汇入下库，而不是直接流到城市。
- **"When relevant" 和第 4 步**：三份答案都用上了梯级相关的检查，也写了审批和授权，PR 比 A 高 1.0 分。
- **保留了第二轮的优势**：不可回头点、各起泄时间所需的泄量、算术核对。裁判逐项复核了这些数字，基本都对。
- **三份答案都发现了题目里的一处数据矛盾**：2.5 亿 m³ 摊到 72 小时，平均流量低于当前入流。答案都把这一点写成了明确的假设。

## 仍需注意

1. **全部是小胜**：6 票都是 "slight"，没有一票是 "clear"。U5 本来就是 A 也答得比较好的题。
2. **CA 略低于 A（7.5 对 8.0）**：
   - 裁判指出 C 有几处说得偏满，例如"放空防洪库容几乎没有代价"、"在整个预报范围内都稳健"。
   - 前一句可能与 J13（防洪区要尽快排空）有关。答案据此认为放空没有代价，但裁判认为，在确认这部分库容确实是防洪库容之前，这么说过于肯定了。
   - 这一点暂时不改。最终测试时留意是否在其他题里重复出现。
3. **TC 略低（7.8 对 8.0）**：r2 有两处数字前后不一致，对结论影响不大。
4. **其他 6 道题没有重跑**：v3 第 4 步收紧后，其他题可能受到影响，比如篇幅变长。这一点交给 V01–V05 最终测试检验。
