# Round 01 结果报告（skill v1）

日期：2026-10-28

## 测试设置

- **对比方式**：A 组不用 skill，C 组用 skill v1（冻结版本：`skill-tested/`）。
- **题目**：U1–U7，共 7 道开发题。

- **裁判**：每道题由 2 位 Opus 5.5 裁判盲评，两位裁判看到的答案顺序相反。

## 一、总体结果

| 答题模型 | 题目层面 C 胜 / A 胜 / 意见不一 | 偏向 C 的判定 | 平均分 A → C |
|---|---|---|---|
| Opus 5.5 | 4 / 0 / 3 | 11/14 | 7.73 → 8.19（+0.46） |
| Sonnet 5.5 | 4 / 0 / 3 | 11/14 | 7.33 → 7.69（+0.36） |
| Haiku 4.5 | 3 / 3 / 1 | 7/14 | 5.11 → 5.33（+0.22） |

- **Opus 和 Sonnet**：C 一题都没输，但优势很小。42 份判定中只有 8 份判为明显胜出（clear），其余都是小胜（slight）。
- **Haiku**：输赢各半。用了 skill 以后，CA（判断有没有依据、是否说过头）平均下降 0.8 分。

## 二、这批数据有多可信

1. **位置效应**：第一位裁判 21 次中有 17 次选了排在第二位的答案，而 C 只有 10 次排在第二位。5 个两位裁判意见相反的格子，两位裁判都选了排在第二位的答案，应视为平局。
2. **裁判的算术错误**：opus-U6 的第二位裁判认为 C 写的"50 年超越概率 48%"错了。实际上 1−0.987⁵⁰ ≈ 0.48，C 是对的，属于误扣。
3. **答案长度**："C 比 A 多写的字数"和"C 比 A 多得的分数"之间相关系数只有 r = 0.24。分数提升主要不是因为写得更长。

## 三、skill 帮上忙的地方（裁判反复提到）

1. **给预报价值定上下界**：分别在无预报、实际预报和完美预报三种条件下评估。这是 C 最稳定的优势，A 组几乎都没有做。
2. **先检查可行性**：在有效预见期内能否完成预泄或消落，泄流能力和下游安全泄量是否允许。
3. **先定基准和验收标准**：以现行调度规则为基准，事先写清楚"怎样才算更好"。
4. **先验证模拟器本身**：用历史放流回放，看能否复现实测水位；闸门开度取整后，再用全模型复核一次。
5. **结论有边界**：安全不能用效益换取；数据只够说"有希望"时，就只说"有希望"。

**分题目看**：U1（研究设计）、U2（计算）、U7（方法选择）三道题 C 全胜，共 18/18 份判定。U3–U6（复盘、决策、治理类）C 没有优势，部分题还输了。

## 四、skill 带来的问题（主要出现在 Haiku，Sonnet 也有）

1. **把 skill 当文献引用**：例如"50 篇论文发现……"、"papers show……"。Haiku 有 5 道题、Sonnet 有 3 道题因此被扣 CA 分。A 组一次也没有出现。
2. **泄露内部编号**：答案里出现了 E23-R4、RP05-B、Stage 1–4 等 skill 内部编号。
3. **编造事实**：Haiku 的 C 组答案凭空写出了 HEFS、SOBEK、"NSE≈0.97"，还编造了一个置信区间。
4. **清单挤掉了关键问题**：
   - haiku-U6：答案先说"防洪风险不可补偿"，最后却推荐了会抬高防洪风险的方案。
   - haiku-U4：把题目真正要问的"实时预报能否获得"直接当成了前提。

## 五、两组都漏掉的要点（与 skill 无关）

21 个组合 = 7 道题 × 3 个模型。

| 漏掉的点 | 出现组合数 |
|---|---|
| 正式审批路径与法定运行依据 | 19 |
| 数量级算例（例如预泄体积 = 净泄量 × 时间，再与库容比较） | 12 |
| 概率与样本量的算术（1−(1−p)ⁿ、二项分布标准误等） | 12 |
| 中止与回退方案、误报的代价 | 9 |
| 从抬高后的水位起调演算设计洪水和校核洪水 | 8 |
| 洪水传播时间 | 7 |

**核心问题**：skill 让答案的框架更完整，但该算的数仍然没有算。
