## 二、裁判认为 v2 改进起作用的地方

- **算出了数量级（How to work 第 6 步，以及 J05、J08、J16、J17）**：
  - U1：1 − 0.99³ ≈ 2.97%，并估算了 40 km 的传播时间。
  - U2：可用净泄量 × 28 h ≈ 2.32 亿 m³。
  - U3：核对了在 3 天内削峰 18% 在物理上是否可行。
  - U4：按质量守恒推算所需库容约 2.6 亿 m³，并算出 13 年内出现百年一遇洪水的概率约 12%。
  - U6：估算了需要多少模拟年才能区分各方案的洪水概率。
  - U7：51 个集合成员分辨不了低于约 2% 的概率；20 年回报预报中独立洪水很少。
- **先找决定性问题（第 2 步）**：U3 和 U4 的裁判都提到 C "排出了决定性问题"，而 A 的问题清单没有排序。
- **审批与回退写得具体了（J19–J21）**：
  - U1 写出了印度的审批路径：Dam Safety Act 2021、邦大坝安全机构、NDSA。
  - U3 写出了事先约定的验收标准、一个汛期的影子运行，以及回退触发条件。
  - U7 写出了有名称的回退触发条件。
  - PR 一项的差值从 +0.1 升到 +1.6，是提升最大的一项。
- **U5 用上了 J13**：答案以"汛限以上蓄量属于防洪库容，必须腾空"为前提，算出了不可回头点（第 15–18 小时）。两位裁判都把这一点列为优点。

## 三、仍然存在的问题

### 1. U5 仍然没有赢

两位裁判对 C 的批评：
- 小的算术错误：5,100 应为约 4,900 m³/s。
- 压力测试没有计入基流，答案中出现的 9,500 m³/s 没有定义来源。
- 下库库容先跟洪量比较，没有扣除支流要占用的部分。
- 下泄前没有做多情景的洪水演算（支流洪水早到、同时到、晚到）。
- 下库在洪水期的补偿泄流规则只写了一部分。

两位裁判都认为两组都漏了：
- 两座坝之间河道的过流能力。
- 上下两库如何分配联合防洪库容。
- 在 150–400 的预报范围内，高值情景要有多大概率才值得预泄。

### 2. 其他题里 C 仍有的小问题

- U1：把城镇的安全流量限值用在了净消落速率上，应该用在下泄流量上。
- U4：把预泄速率的上限归为泄洪设施能力，实际起控制作用的是下游安全泄量。
- U6：把"A 方案风险上界 ≤ 1.0%"作为采用条件，而 A 的点估计正好是 1.0%，这个条件几乎不可能满足。
- U7：有一处没有来源的说法（别处的运行时间）。

### 3. 答案长度

C 平均 3,275 词，A 平均 2,838 词，C 长 15%（第一轮只长 3%）。7 道题里，"多写的字数"和"多得的分数"的相关系数 r = 0.79，只有 7 个数据点，比较粗糙；第一轮 21 组时是 0.24。

但长度解释不了全部提升：
- U4 的 C 比 A 略短，仍然两票都胜。
- U2 的 C 长了 67%，裁判给 C 加分的理由是"算出了数"，不是"写得多"。

裁判 prompt 里已经写了 "Do not reward length"，但仍然不能排除长度的影响。

## 四、可信度提醒

- **A 组答案完全相同，得分却从 7.73 降到 7.46**：说明裁判打分是相对的，C 越强，A 的分越低。所以"平均分差"会放大真实差距。胜负和 clear 票数更可靠。
- **位置偏差减弱**：第一位裁判选第二个位置的比例，第一轮是 17/21；这一轮两位裁判在 7 道题中有 6 道结论一致，只有 U5 意见不一。
- **样本量小**：每个版本只跑了一次，只有 7 道题。C 组答案每次重跑都会有波动。
